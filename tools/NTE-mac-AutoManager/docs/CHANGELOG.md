# 版本紀錄

## 0.1.1 全螢幕選取修正

視窗下拉清單改為包含其他桌面的視窗；新增倒數後依前景 App 鎖定最大可見視窗。這一步不點擊、不按鍵。實際擷取及操作仍只允許目標遊戲在前景並完全可見；不在前景會停止。若仍無法找到視窗，確認系統「螢幕與系統音訊錄製／螢幕錄製」已允許新版 App，然後退出工具再重開。

## 0.1.2 預設自動套用

首次執行或舊版尚未建立模板時，自動安裝使用者附圖的辨識模板、點擊位置、訂單區域及星星／活力設定。手動校準收進預設折疊的進階區域。既有自訂校準不會被自動覆蓋。這是依附圖預先設定及畫面正規化，不是對任意新介面都能無資料地自動學習；不匹配時仍會停止。

## 0.1.3 開始時自動重新鎖定

不再以保存的視窗編號啟動。按開始後有 5 秒切換時間，接著最多等候 12 秒，確認前景為 `com.hottagames.nte` 且視窗編號／尺寸連續穩定後，才開始辨識及操作。每次重新綁定會寫入紀錄。請切回遊戲後保持約 20 秒再觀察結果；過早切回工具會使前景保護停止。

「找不到選取的視窗」可能來自舊編號，也可能是遊戲位於另一個桌面而不在當下可見清單，不能僅從這個訊息判定是哪一種。更新同時處理兩種情況；運行中的前景與遮擋保護仍保留。

## 0.1.4 快速捲動與較低顧客訂單

預設每次向上捲動為 4 個 30 行事件，間隔 0.08 秒，之後仍確認 1-1 及右側標題再開始。擴大顧客氣泡搜尋高度，修正較矮／較低顧客的底部指標落在搜尋範圍外而被判定無訂單的問題。營業時只計算相關辨識，避免反覆搜尋選關文字。

已知舊版內建訂單區域及捲動量會自動升級，不必重新框選；手動自訂的訂單區域保留。每兩秒記錄營業辨識狀態，方便診斷。尺寸變更只會在重新擷取前採用，仍需同一個 PID／視窗、保持前景且沒有遮擋；擷取途中若變更，丟棄舊圖重試，最多三次。

## 0.1.5 全顧客區域動態搜尋（目前預設）

以整個顧客區域（畫面寬度 1%–99%、高度 4%–56%，避開桌面材料）搜尋所有氣泡底部指標，再依各指標上方的局部區域辨識飲料。多尺度候選會去除重複，並以位置追蹤最多八個氣泡，避免同一訂單因顧客移動而重複製作。超過八個候選會停止檢查。預設不再使用三個固定顧客框；原有手動自訂框仍保留，新增手動訂單框會切回自訂模式。

已知舊版內建設定會自動升級成此模式，無須重新載入預設或框選。繼承 0.1.4 的快速上捲、重新擷取後更新尺寸、辨識狀態紀錄。仍需要遊戲中的氣泡外觀符合模板；此更新擴大位置覆蓋，不代表任何未知 UI 外觀都已驗證。

## 0.1.6 出餐確認修正

預設訂單皆先嘗試番茄汁；辨識氣泡的縮放範圍擴大，標記門檻降至 0.88。修正遊戲送給另一位顧客後卡住的問題。材料點完後的完成等待為 1 秒，失敗走既有畫面確認結算流程。既有附圖設定會自動升級，不必重新校準。自訂設定仍保留。

訂單消失是畫面上的完成代理訊號；短暫遮擋可能誤判，顧客立即被替換而沒有空檔則可能提前結算。此版採使用者要求的寬鬆策略，仍需遊戲實測。

## 0.1.7 即見即做

預設模式不再等待同一筆訂單連續三幀確認。第一次看見營業 HUD 與訂單就做完整配方：杯子 → 0.12 秒 → 材料包；中間不截圖、不重新辨識，但每次輸入仍檢查前景、視窗座標和停止訊號。任一筆訂單完成時，若畫面已有下一單，當次直接做下一杯。材料點完後仍維持 1 秒未完成即 Esc 的設定（下一次截圖辨識完成時檢查）。

縮小搜尋影像找氣泡候選，再在原尺寸局部驗證；預設模式略過飲料種類比對。日誌新增版本、擷取及辨識耗時，便於分辨遊戲運行負載下的瓶頸。

## 0.1.8 兩單立即結算

依使用者指定，預設以兩次完整配方送出為一局。計數發生在材料實際點擊完成後，每局重設；不把預排操作或兩單策略計為已辨識三星。前景、停止及座標保護逐次檢查。關卡選擇和結算按鈕改為單次畫面確認，避免額外三幀等待，仍須辨識對應畫面才點擊。次數設 0 可持續循環，直到手動停止、活力歸零或保護條件觸發。

## 0.1.9 擷取加速、微量變化與清除截圖

改用同一程式內的 Apple ScreenCaptureKit（macOS 14+）直接擷取視窗到記憶體，以 1920 像素寬度輸出。保留每張擷取前後的前景／遮擋／座標檢查。若快速 API 不可用，日誌會顯示原因並降回舊擷取；舊方法較慢。正常影格不寫入硬碟，只在錯誤或保護停止時保留診斷截圖。API 參考：https://developer.apple.com/documentation/screencapturekit/scscreenshotmanager/captureimage(contentfilter:configuration:completionhandler:)

氣泡候選改用縮小的灰階影像搜尋，仍用原尺寸彩色區域驗證；限制 OpenCV 為兩個執行緒，減少與遊戲爭用 CPU。辨識只執行當前流程所需的模板。第一張營業畫面已有訂單時就可出餐。輪詢等待降至 20 毫秒。

點擊中心每軸最多 ±1 macOS 邏輯點（Retina 約 2 像素），按下／配方間隔最多 ±4 毫秒。位置會限制在遊戲內容範圍，按下和放開使用同一座標。設定 `click_jitter_points: 0`、`time_jitter_seconds: 0` 可關閉；不宣稱能避免遊戲辨識自動化。材料點完至下一杯或 Esc 留約 80 毫秒緩衝，讓遊戲處理輸入；仍需實機確認是否有漏接。

主畫面「清除執行截圖」一鍵刪除本工具 logs 下符合命名的 `*-error.png`、`*-stopped.png`，顯示刪除數量及釋放空間。不刪文字日誌、校準、模板或自行匯入的圖片，不跟隨符號連結、不遞迴刪除。運行後若再發生錯誤，仍可能產生新的診斷截圖。

## 0.1.10 載入／暫時畫面等待

快速擷取會看到以前慢速擷取跳過的轉場。黑畫面、部分淡入或目前狀態辨識不到可操作畫面時，工具等待並停止輸入；畫面恢復便接續原流程，不因黑畫面持續幾秒而退出。等待時間不計入製作、狀態或單局逾時；可隨時停止。網路提示若無法辨識為可操作畫面，同樣等待，不盲點重試或重新登入。若提示需要手動處理，請停止工具後處理再開始。

前景、視窗遮擋、遊戲關閉、權限等實際操作錯誤仍會停止。看得見且可操作時，既有出餐一秒未完成與其他流程保護仍有效。保留快速擷取、兩單結算、微量點擊變化與清除截圖按鈕。

## 0.1.11–0.1.12 轉場、訂單門檻與挑戰失敗

全螢幕或載入轉場造成的畫面比例短暫不符改為等待，持續超過 10 秒才停止。訂單氣泡門檻由 0.88 降到 0.84，修正忙碌背景上的氣泡（約 0.87）被漏看；連擊圖示最高約 0.82，因此不再往下調。營業中持續沒看到訂單時，最多保存五張診斷截圖 `*-noorder-N.png`，「清除執行截圖」也會一併清除。

新增「挑戰失敗」畫面辨識：不等待活力數字，直接點「退出」，每 2 秒重試一次，超過狀態逾時就停止。既有設定會自動加入此模板與點位，其他校準保留。

## 0.1.13 截圖殘留視窗與短暫遮擋

macOS 的 `screencaptureui` 在截圖後可能留下看不見的全螢幕視窗，舊版會因此判定遊戲被遮住而停止。現在依 bundle id 略過它。其他遮擋先暫停操作最多等 3 秒，消失就繼續；仍被遮住才停止，錯誤訊息會列出遮擋的程式名稱。
